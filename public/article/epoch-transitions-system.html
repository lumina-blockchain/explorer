Epoch Transitions, Persistent Accumulator & Scheduled Payouts

Bagaimana Lumina L1 menunda dan merapalkan bagi hasil (Block Reward & Gas Fee) ke titik transisi terjadwal setiap 100 blok sekali untuk performa TPS ekstrem dan mencegah State Bloat.

Dalam desain blockchain tradisional (seperti Ethereum atau Bitcoin), reward penambangan dan biaya gas didistribusikan secara instan pada setiap blok yang sukses dimasukkan ke dalam rantai. Walaupun terlihat sederhana, pendekatan eceran ini memiliki dampak buruk yang sangat fatal bagi performa throughput (TPS) jaringan jangka panjang: State Bloat & High Database Write Overhead.

Setiap blok baru mengharuskan mesin eksekusi melakukan pembagian receh (*dust balance updates*) ke puluhan validator. Hal ini memicu antrean panjang operasi tulis (*disk writes*) pada database state RocksDB/Sled, memperlambat pemrosesan transaksi pengguna, dan membuang-buang bandwidth konsensus secara sia-sia.

💡 Pendekatan Lumina L1: Memperkenalkan sistem Epoch Transitions. Seluruh jatah gaji validator (Leader & Top 30 Elite Stakers) diakumulasikan secara aman di latar belakang, lalu dibayarkan secara rapelan (batch) otomatis tepat saat masa transisi setiap 100 blok sekali.

1. Arsitektur Brankas Akumulasi (Persistent Accumulator)

Untuk mengamankan reward dan fee selama Epoch berjalan tanpa memicu pembaharuan saldo langsung pada akun dompet pengguna, Lumina mengimplementasikan sistem celengan persistent di database "validator_keys" menggunakan kunci khusus:

  • epoch_leader_reward:<address>: Menyimpan total jatah block reward + 10% gas fee bonus untuk masing-masing leader yang memproposalkan blok selama Epoch tersebut.
  • epoch_accumulated_shared_pool: Mengumpulkan total 90% porsi sisa gas fee transaksi untuk didistribusikan ke staker elite.
  • epoch_leaders_list: Menyimpan daftar alamat leader yang berkontribusi aktif memproposalkan blok pada Epoch ini.

Tipe data celengan disimpan secara efisien dalam format representasi byte big-endian u128 untuk integritas data yang kokoh:

// Helper Method Celengan di crates/state/src/lib.rs pub fn get_accumulated_value(&self, key: &str) -> u128 { if let Ok(Some(bytes)) = self.db.get("validator_keys", key.as_bytes()) { if bytes.len() == 16 { return u128::from_be_bytes(bytes.try_into().unwrap()); } } 0 } pub fn set_accumulated_value(&self, key: &str, val: u128) { let _ = self.db.put("validator_keys", key.as_bytes(), &val.to_be_bytes()); }

2. Protokol Tutup Buku Otomatis (Epoch Transition Block)

Saat tinggi blok menyentuh kelipatan 100 (misalnya blok #100, #200, dst.), State Engine secara otomatis mengaktifkan siklus tutup buku desentralisasi di akhir tahap finalisasi blok:

💸 1. Gajian Rapelan Leader

Sistem memproses daftar leader di epoch_leaders_list, mentransfer seluruh reward akumulatif ke saldo wallet mereka, lalu membersihkan datanya dari database.

👑 2. Distribusi Pool Elite (Top 30)

Sistem mengambil saldo epoch_accumulated_shared_pool, lalu membagikannya secara proporsional ke Top 30 staker aktif berdasarkan bobot staked mereka saat transisi terjadi.

🛡️ Nol Downtime & Keamanan Desentralisasi: Transaksi user (seperti kirim koin & deploy contract) di blok transisi tetap diproses instan tanpa delay! Seluruh proses bagi hasil diselesaikan secara deterministik oleh seluruh node validator pada tahap akhir eksekusi blok.
