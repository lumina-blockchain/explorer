Pertahanan Berlapis: Rate Limiting & Authentication Middleware Berkinerja Tinggi

Bagaimana Lumina L1 memproteksi API publik dan premium menggunakan algoritma Token Bucket in-memory yang cepat dan sistem autentikasi multi-format.

STATUS KEAMANAN: MIDDLEWARE AKTIF

Node blockchain publik sering kali menjadi target empuk serangan penyalahgunaan jaringan. Dari bot dApp yang mengirimkan permintaan secara tidak efisien hingga penyerang jahat yang mencoba melakukan spamming transaksi mempool dan pemanggilan smart contract berat, ketiadaan mekanisme kontrol akses dapat menyebabkan kelumpuhan server.

Lumina L1 mengatasi masalah krusial ini dengan memperkenalkan Rate Limiting & Authentication Middleware kustom yang dirancang menggunakan framework Axum asinkronus dalam Rust. Implementasi ini menjamin node tetap stabil di bawah beban puncak, serta membatasi konsumsi sumber daya CPU dan I/O disk secara efisien.

💡 ANALOGI NYATA: Pesta Terbuka vs Pintu Masuk VIP dengan Pembatas Kecepatan

1. API Tanpa Proteksi (Pesta Terbuka): Siapa saja boleh masuk, dan satu tamu serakah dapat mengambil semua piring makanan di meja prasmanan sekaligus. Server Anda akan mogok karena kewalahan melayani tamu yang tamak ini.

2. Autentikasi (Penjaga Pintu VIP): Hanya tamu dengan undangan resmi (API Key) yang boleh melangkah masuk. Tamu tak diundang langsung diusir di pintu masuk dengan respon HTTP 401 Unauthorized.

3. Rate Limiting (Ember Pengatur Kecepatan - Token Bucket): Setiap tamu diberikan kuota maksimum kelereng (koin token) saat masuk. Setiap kali mereka meminta makanan (request API), mereka harus menyerahkan satu kelereng. Jika kelereng habis, mereka harus mengantre dan menunggu kelereng tersebut terisi kembali secara berkala (Refill Rate). Jika memaksa meminta saat kelereng kosong, mereka ditolak dengan kode error HTTP 429 Too Many Requests.

Sistem Autentikasi Fleksibel (API Key)

Untuk menyederhanakan integrasi client SDK, middleware autentikasi Lumina dirancang untuk mendeteksi kunci keamanan API Key melalui tiga metode secara paralel:

1. Header Authorization Bearer

Format standar HTTP global. Dideteksi dari header Authorization: Bearer atau langsung Authorization: .

2. Header Kustom X-API-Key

Header khusus yang sangat populer bagi kalangan developer dApp. Cukup sertakan header X-API-Key: pada request.

3. URL Query Parameter

Sangat berguna untuk akses cepat melalui browser atau curl sederhana. Mendukung parameter ?apikey=, ?api_key=, maupun ?key=.

4. Deteksi Otonom & Bypass

Jika parameter CLI --api-key tidak diaktifkan pada node, middleware akan menonaktifkan pengecekan kunci secara otomatis demi kenyamanan pengembangan lokal.

Algoritma Pembatasan Trafik: Token Bucket

Rate limiter Lumina didesain secara internal (in-memory) tanpa dependensi Redis eksternal yang lambat. Keadaan ember (*state bucket*) disimpan dalam format aman konkurensi (thread-safe hash map) di memori RAM, yang menghitung masa berlaku token secara asinkronus:

  • Max Tokens (Kapasitas Ember): Jumlah burst maksimal yang diperbolehkan untuk satu IP (misal: 100 request sekaligus).
  • Refill Rate (Kecepatan Refill): Jumlah token baru yang ditambahkan kembali ke ember per detik (misal: 2.0 token per detik).
  • Deteksi IP Proxy Cerdas: Mendeteksi alamat IP asli client di belakang Cloudflare/Nginx proxy melalui header X-Forwarded-For dan X-Real-IP, sebelum melakukan fallback ke ConnectInfo dari TCP socket.

Contoh Respon Error Autentikasi Gagal (HTTP 401):

{ "jsonrpc": "2.0", "error": { "code": -32001, "message": "Unauthorized: invalid or missing API key" }, "id": null }

Contoh Respon Error Batas Limit Tercapai (HTTP 429):

{ "jsonrpc": "2.0", "error": { "code": -32005, "message": "Too Many Requests: rate limit exceeded" }, "id": null }

Konfigurasi CLI untuk Operator Node

Operator node Lumina dapat dengan mudah mengaktifkan pengamanan ini melalui CLI arguments saat menyalakan node:

lumina-node --api-key lumina_secret_key_123 --rate-limit-max 150 --rate-limit-refill 5.0

Dengan perintah di atas, node akan mengharuskan client menyertakan key lumina_secret_key_123 dan membatasi setiap IP unik maksimal 150 request burst dengan kecepatan isi ulang token 5 request per detik.
