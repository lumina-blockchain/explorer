Custom Fee Market & Mempool Priority Sorting

Mekanisme prioritas transaksi berbasis ekonomi untuk meningkatkan throughput transaksi sekaligus melindungi jaringan dari ancaman spam.

Pada jaringan blockchain modern, ledakan lalu lintas transaksi (*surging traffic*) dapat dengan mudah menyebabkan kemacetan jaringan (*network congestion*). Jika transaksi diproses semata-mata berdasarkan urutan waktu masuk (*First-In-First-Out*), penyerang dapat melumpuhkan jaringan dengan membanjiri transaksi bernilai kecil secara massal.

Lumina memecahkan masalah ini melalui implementasi **Custom Fee Market** (Pasar Gas Fee Khusus). Pengguna dapat membubuhkan **Priority Fee (tips)** opsional ke dalam transaksi mereka. Engine konsensus kemudian mengurutkan antrean mempool secara kompetitif untuk memilih transaksi dengan nilai insentif terbaik demi efisiensi ekonomi validator.

💡 Keamanan Transaksi Presisi: Untuk menghindari pembulatan matematis atau kegagalan parsing nilai u128 astronomis di JSON API, Lumina menggunakan String-based Submission (mengirim angka besar sebagai string valueString dan feeString) yang dikonversi langsung di tingkat kernel Rust node.

1. Logika Pengurutan Mempool (Priority Sorting Logic)

Di dalam modul mempool Lumina (crates/consensus/src/mempool.rs), transaksi tidak pernah diurutkan berdasarkan urutan waktu semata. Transaksi diurutkan menggunakan kriteria berjenjang:

📈 Kriteria Utama: Fee Tertinggi

Mempool memilah dan menaikkan transaksi yang menawarkan biaya gas/tips paling tinggi ke puncak antrean. Ini memberikan kepastian proses bagi pengguna yang membutuhkan kecepatan eksekusi tinggi.

🔢 Kriteria Kedua: Nonce Terendah

Untuk transaksi dari pengirim yang sama (*same sender address*), urutan eksekusi wajib dipertahankan dari Nonce terkecil ke terbesar guna mencegah kegagalan state transition.

2. Implementasi Rust: Kode Pengurutan Mempool

Di bawah ini adalah implementasi nyata dari fungsi get_batch di dalam mempool core Rust Lumina:

/// Ambil batch transaksi dari mempool yang sudah terurut berdasarkan prioritas ekonomi. pub fn get_batch(&self, limit: usize) -> Vec<SignedTransaction> { let mut entries: Vec<MempoolEntry> = self.pending_transactions .iter() .map(|kv| kv.value().clone()) .collect(); // --- LOGIKA PRIORITAS EKONOMI --- // 1. Urutkan berdasarkan Fee tertinggi (Custom Priority) // 2. Jika Fee sama, urutkan berdasarkan Nonce terendah (urutan transaksi pengirim) entries.sort_by(|a, b| { b.tx.transaction.fee.cmp(&a.tx.transaction.fee) .then_with(|| a.tx.transaction.nonce.cmp(&b.tx.transaction.nonce)) }); entries.into_iter() .take(limit) .map(|e| e.tx) .collect() }

3. Mekanisme Proteksi Lonjakan (Surge Protection)

Selain memprioritaskan biaya transaksi, mempool Lumina dilengkapi dengan **Surge Protection System** untuk membatasi ukuran buffer antrean:

🛡️ Kapasitas Maksimal Mempool (MAX_MEMPOOL_SIZE)

Kapasitas maksimum mempool dibatasi secara ketat hingga **50,000 Transaksi**. Jika batas ini terlampaui saat terjadi lonjakan masif, node secara otomatis mengaktifkan mode proteksi dan menolak transaksi baru dengan respons kesalahan: "Mempool is full! Surge protection active.".

4. Siklus Hidup Transaksi Basi (TTL & Expiration)

Transaksi yang tertahan terlalu lama di mempool karena menawarkan biaya terlalu rendah tidak akan menyumbat mempool selamanya. Setiap kali blok baru diproduksi, node menjalankan fungsi pembersihan:

  • Waktu Kedaluwarsa (TTL): Transaksi akan dianggap basi jika bertahan lebih dari **10 Blok** sejak dimasukkan.
  • Arsip Otomatis: Transaksi basi tidak dibuang begitu saja. Node secara otomatis mengarsipkan transaksi tersebut ke dalam StateManager melalui method record_dropped_transaction beserta pencatatan estimasi gas fee dinamisnya.
