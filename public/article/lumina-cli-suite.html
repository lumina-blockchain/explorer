Mastering Lumina CLI Suite: Navigasi, Staking & Tata Kelola Banding Validator

Panduan lengkap menguasai antarmuka baris perintah (CLI) Lumina untuk mengelola aset, memantau integritas validator pool, hingga berpartisipasi dalam proses banding konsensus BFT.

Halo para Pengembang dan Operator Node Lumina! Selain menyediakan SDK Javascript dan API gRPC/WebSocket yang canggih, tim inti Lumina juga menyediakan perangkat utama terintegrasi untuk berinteraksi langsung dengan blockchain dari terminal kesayanganmu: Lumina CLI (lumina-cli).

Lumina CLI ditulis menggunakan Rust untuk performa dan keamanan optimal, memungkinkan penandatanganan transaksi secara lokal tanpa memaparkan private key ke internet. Melalui artikel ini, kita akan bedah habis setiap fiturnya secara detail: mulai dari manajemen dompet offline, melakukan staking, melakukan kueri status validator pool secara real-time, hingga mekanisme penyelamatan validator saat terkena masa jeling (jailing) akibat pelanggaran BFT.

💡 Mengapa Transaksi CLI Sangat Aman? Di Lumina L1, seluruh private key yang dimasukkan ke CLI diolah dan ditandatangani 100% di memori lokal laptop/mesin-mu sebelum dikirim sebagai signed transaction ke RPC endpoint node. Kunci rahasiamu tidak pernah dikirim melintasi jaringan internet atau ditulis ke penyimpanan disk!

1. Instalasi dan Opsi Global CLI

Secara default, binary CLI dapat dipanggil menggunakan nama lumina-cli. Perangkat ini mendukung konfigurasi parameter global yang mempermudah koneksi ke node jaringan mana saja:

# Menampilkan bantuan menu utama dan seluruh subcommand $ lumina-cli --help # Menghubungkan CLI ke Custom RPC Endpoint (misalnya Testnet publik) $ lumina-cli --rpc https://rpc.testnet.lumina.tech latest
Global Parameter Keterangan Nilai Default
--rpc <URL> URL endpoint RPC HTTP node Lumina yang ditargetkan untuk query/kirim transaksi. http://127.0.0.1:9098
--api-key <KEY> Token otentikasi opsional jika node target menerapkan proteksi rate-limiting. None

2. Manajemen Dompet Offline (Subcommand: wallet)

Untuk bertransaksi di jaringan Lumina, kamu memerlukan sebuah dompet (wallet) yang diwakili oleh kunci rahasia (private key) dan alamat publik berbasis format Bech32m dengan prefix lumina1....

A. Membuat Wallet Baru

Kamu bisa membuat wallet acak yang baru secara aman dan offline menggunakan perintah berikut:

$ lumina-cli wallet generate

Perintah di atas akan mencetak tiga data penting di terminalmu:

  • Address: Alamat publik penerima koin (berawalan lumina1...).
  • Public Key: Representasi publik kunci dalam format hex.
  • Private Key: Kunci rahasia dompetmu dalam format hex. Simpan ini di tempat teraman!

B. Memulihkan Wallet

Jika kamu sudah memiliki kunci rahasia atau seed phrase sebelumnya, kamu bisa memulihkannya secara instan:

# Memulihkan wallet dari Private Key Hex (64 karakter) $ lumina-cli wallet from-secret "c37429dc912e4913b6..." # Memulihkan wallet dari 12 atau 24 kata Mnemonic master seed phrase $ lumina-cli wallet from-mnemonic "apple banana cherry dog elephant fox grape horse ice jacket kangaroo lemon" --index 0

C. Mendaftarkan Alias Dompet On-Chain (Subcommand: wallet set-name)

Lumina mendukung pendaftaran alias nama dompet unik secara on-chain. Nama alias ini akan mempermudah pelacakan identitas validator milikmu di penelusur scan:

# Mendaftarkan nama alias on-chain untuk alamat dompet Anda $ lumina-cli wallet set-name --secret "c3742..." --name "Gamer-Node"

3. Transfer, Saldo & Penelusuran Jaringan

Setelah wallet siap, kamu bisa melakukan pengecekan saldo, nonce, dan memindahkan aset dengan cepat.

A. Memeriksa Saldo & Nonce Akun (Subcommand: balance)

Memeriksa saldo (dalam satuan Lumlets) dan nonce aktif dari alamat dompet tertentu:

$ lumina-cli balance lumina1qqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqq4fdvjl

B. Mengecek Nonce Akun Secara Mandiri (Subcommand: nonce)

Nonce menunjukkan jumlah transaksi keluar dari akun Anda, sangat berguna untuk melacak antrean transaksi:

$ lumina-cli nonce lumina1qqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqq4fdvjl

C. Mengirim Transfer Koin (Subcommand: transfer)

Mengirim koin ke dompet lain dengan fee transaksi yang dapat diatur secara opsional:

# Mengirim transfer koin (100.000.000.000 Lumlets = 0.0001 LUM) $ lumina-cli transfer --secret "c3742..." --to "lumina1abc..." --amount 100000000000

D. Mengambil Data Blok Terbaru & Tertentu (Subcommand: block & latest)

Mendapatkan data informasi struktur blok (seperti hash transaksi, state root, block height) secara langsung:

# Melihat tinggi blok terbaru di jaringan saat ini $ lumina-cli latest # Melihat detail data blok pada ketinggian tertentu $ lumina-cli block 420

E. Melakukan Pencarian Global (Subcommand: search)

Mencari transaksi berdasarkan hash, blok berdasarkan tinggi, atau info akun berdasarkan alamat dompet secara dinamis:

$ lumina-cli search "lumina1abc..."

4. Melakukan Staking Ke Validator Pool

Untuk mendaftarkan server validator-mu agar berhak memproduksi blok dan memperoleh imbal hasil gas fee, kamu wajib mengunci minimal 10.000 LUM (setara 10,000,000,000,000,000,000,000 Lumlets) sebagai jaminan modal komitmen:

# Melakukan transaksi STAKE untuk mendaftarkan validator $ lumina-cli stake --secret "c3742..." --amount 10000000000000000000000

Di balik layar, perintah stake ini secara otomatis memformat transaksi khusus dengan tujuan Zero Address (seluruh byte bernilai nol) dan menyisipkan payload pesan biner STAKE ke dalam field data transaksi yang akan diverifikasi oleh aturan konsensus secara on-chain.

5. Memantau Status Jaringan Validator

Operator node wajib memantau kesehatan kolam validator agar tidak kehilangan hak partisipasi konsensus. Perintah validator menyediakan informasi live tersebut:

# Menampilkan daftar seluruh validator di jaringan beserta statusnya $ lumina-cli validator list

Perintah di atas akan mencetak tabel live cantik yang menyajikan profil validator dengan status:

  • 🟩 Active : Validator aktif memproduksi blok dan meraup reward.
  • 🟥 Jailed : Validator sedang dihukum (ditangguhkan) karena sering absen memvalidasi blok.
  • ⬜ Inactive : Staking terdaftar namun modal di bawah ambang batas minimal atau ditarik keluar.

Untuk melihat rekam jejak performa detail validator tertentu:

$ lumina-cli validator info lumina1abc...

💡 Pantau Missed Blocks: Jika total kegagalan memvalidasi blok (missed_blocks) validator milikmu bertambah terus mendekati batas ambang toleransi sistem, bersiaplah! Node-mu akan dijatuhi hukuman Jailed secara otomatis oleh protokol BFT demi menjaga keandalan konsensus.

6. Fitur Elite: Tata Kelola Banding BFT (Governance Appeal)

Apabila jaringan mendeteksi performa validator menurun drastis, statusnya akan bergeser menjadi Jailed. Pada status ini, hak memproduksi blok dicabut sementara, dan validator tidak menerima porsi pendapatan gas fee.

Namun jangan panik! Lumina menyediakan alur banding demokratis berbasis on-chain menggunakan sub-menu governance.

1. Validator Jailed
➔
2. Kirim APPEAL via CLI
➔
3. Voting Validator Aktif
➔
4. Quorum Terpenuhi -> Active Kembali

Langkah 1: Mengajukan Banding (Appeal)

Jika servermu telah kembali online dengan koneksi internet yang stabil dan sinkronisasi data yang sempurna, ajukan banding untuk mengembalikan status validator ke Active:

# Mengirimkan transaksi permohonan banding (Appeal) $ lumina-cli governance appeal --secret "c3742..."

Di balik layar, transaksi ini dikirim ke alamat tata kelola sistem resmi (System Address):

lumina1qqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqq4fdvjl

Dengan menyisipkan payload instruksi biner APPEAL, status banding validator yang bersangkutan akan berubah menjadi 🟡 PENDING pada profil database on-chain.

Langkah 2: Proses Voting Banding (Vote-Appeal)

Seluruh komunitas validator aktif lainnya berkewajiban untuk memeriksa apakah validator terdakwa sudah layak aktif kembali. Sebagai validator yang baik, kamu bisa memberikan hak suaramu (Setuju atau Menolak) banding milik validator lain melalui CLI:

# Memberikan suara menyetujui (APPROVE) banding validator terdakwa $ lumina-cli governance vote-appeal --secret "c3742_punya_kamu" --target "lumina1_terdakwa..." --decision APPROVE # Atau memberikan suara menolak (REJECT) karena server terdakwa masih offline $ lumina-cli governance vote-appeal --secret "c3742_punya_kamu" --target "lumina1_terdakwa..." --decision REJECT

Setiap transaksi vote-appeal ini dikirim langsung menuju System Address dengan membawa data terstruktur biner berformat: VOTE_APPEAL:alamat_terdakwa:KEPUTUSAN. Konsensus secara otomatis menghitung akumulasi suara secara real-time. Apabila batas quorum setuju terpenuhi, terdakwa akan terbebas dari jerat jailing dan diaktifkan kembali!

⚖️ Catatan Penting Mengenai Klasifikasi Pelanggaran

Apakah semua jenis pelanggaran bisa diajukan banding secara manual melalui CLI? Tidak, Bro! Protokol konsensus Lumina mengklasifikasikan kejahatan menjadi dua tingkatan severity:

  • 1. Pelanggaran Sedang (Medium Severity): Seperti tingginya tingkat downtime atau kegagalan memproduksi blok (missed blocks). Jenis pelanggaran inilah yang berstatus Jailed dan bisa diajukan banding (Appeal) agar pulih.
  • 2. Pelanggaran Berat (High Severity): Seperti double-voting (menandatangani dua blok berbeda di tinggi blok yang sama), memicu pemisahan jaringan sengaja (split-brain), atau kebocoran kunci konsensus secara ilegal. Pelanggaran berat ini akan dideteksi oleh modul Sentinel, memicu slashing permanen 98% modal stake, dan validator diasingkan secara permanen tanpa hak pengajuan banding!

7. Fitur Notifikasi & Telegram Alert (Subcommand: alert)

Untuk memastikan operator node selalu mendapatkan informasi terbaru mengenai kesehatan dan kesalahan yang terjadi pada node, Lumina CLI kini dilengkapi dengan fitur manajemen alert terintegrasi dengan Telegram.

A. Menguji Konektivitas Telegram

Anda dapat menguji apakah Token Bot Telegram dan Chat ID Anda valid dengan mengirimkan pesan tes:

# Mengirim pesan pengujian ke Telegram Anda $ lumina-cli alert test --token "123456789:ABCdefGhI..." --chat-id "987654321"

B. Menyimpan Konfigurasi Alert (Setup)

Agar node dapat mengirimkan notifikasi secara otomatis, Anda bisa menyimpan kredensial ke dalam file konfigurasi telegram.json lokal:

# Menyimpan konfigurasi Telegram secara lokal $ lumina-cli alert setup --token "123456789:ABCdefGhI..." --chat-id "987654321"

Setelah file telegram.json berhasil dibuat, node Lumina yang dijalankan pada folder yang sama akan secara otomatis memuat kredensial tersebut dan mengaktifkan integrasi pemberitahuan Telegram tanpa memerlukan konfigurasi variabel lingkungan (env) manual!
