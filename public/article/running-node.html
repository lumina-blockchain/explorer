Running Lumina Node

Panduan menjalankan validator node Lumina melalui baris perintah CLI dan rincian pemuatan identitas kunci otonom.

Node Lumina diproduksi sebagai satu kesatuan executable binary mandiri yang dapat dikustomisasi secara penuh melalui argumen baris perintah CLI. Node ini menangani sinkronisasi transaksi, Gossipsub block broadcast, rotasi Leader HotStuff BFT, dan eksekusi smart contract WASM secara real-time.

1. Perintah Dasar Eksekusi CLI

Gunakan perintah di bawah ini dari root direktori proyek untuk mengompilasi dan mengeksekusi node Lumina dengan parameter khusus:

cargo run -p lumina-node --bin lumina-node --
  --port 61688
  --secret fdc94d54460e2b7e548f2942435b80a905a5a228b30d8c005f2de5f32b8ec802
  --bootnode /ip4/127.0.0.1/tcp/61688/p2p/12D3KooWN...

Untuk operator yang ingin menekan pertumbuhan storage validator, Lumina juga mendukung mode pruned yang tetap mempertahankan perilaku archive sebagai default saat flag pruning tidak diberikan.

cargo run -p lumina-node --bin lumina-node --
  --port 61688
  --db-path data/node-pruned
  --retain-last-blocks 5000000

2. Penjelasan Grid Parameter CLI

Argumen (Short) Format Tipe Penjelasan Fungsi & Keterangan
--port (-p) u16 (default: 61688) Port TCP komunikasi P2P libp2p. Port server RPC HTTP Axum akan dihitung otomatis: 9090 + (p2p_port % 10).
--secret (-s) String (Hex seed) Kunci rahasia Ed25519 (64 karakter hex) yang menjadi basis identitas tanda tangan validator konsensus.
--bootnode (-b) Multiaddr (libp2p format) Alamat multi-address peer pertama yang dikontak untuk bisa masuk ke dalam jaringan validator global.
--retain-last-blocks u64 (opsional) Mengaktifkan mode pruned node dengan hanya menyimpan N block terakhir di disk. Jika flag ini tidak diisi, node tetap berperilaku sebagai archive node dan menyimpan seluruh histori block.

3. Mode Archive vs Pruned

Flag --retain-last-blocks ditujukan untuk operator validator yang ingin mengontrol pertumbuhan storage jangka panjang. Implementasinya dijalankan sebagai background worker, bukan di hot path validasi block, sehingga pruning histori lama tidak menambah beban sinkron pada jalur konsensus utama.

Secara operasional, node akan tetap menunggu ketersediaan snapshot penuh yang aman, lalu menghapus block historis lama secara bertahap di background. Nilai retention yang terlalu kecil juga akan dinaikkan ke batas aman minimum agar proses restore state dari snapshot dan delta replay tetap berjalan stabil.

4. Alur Prioritas Inisialisasi Identitas Node

Salah satu fitur andalan Lumina adalah penanganan identitas validator otonom. Saat dijalankan, node kernel (node/src/main.rs) memindai identitas menggunakan alur prioritas berikut:

Tahap 1: Argumen CLI --secret

Node memeriksa apakah parameter --secret diisikan pada CLI. Jika ada, node membersihkan prefiks 0x, men-decode hex menjadi byte seed, dan memuat kunci validator dari sana.

Tahap 2: File Kunci Lokal node.key

Jika argumen CLI kosong, node mencari file persistent node.key di direktori eksekusi. Jika file tersebut ada, node memuat seed byte (32 byte pertama) dari sana untuk memulihkan identitas lama.

Tahap 3: Pembuatan Otonom (Auto-Generation)

Jika keduanya tidak ditemukan, node secara otomatis memicu generator Ed25519 otonom, menulis biner seed tersebut ke dalam file node.key baru di disk untuk penyimpanan permanen, lalu mencetak Alamat Lumina (Bech32m) yang diturunkan dari public key.

💡 Pro-Tip Pengujian Lokal Multi-Node

Anda dapat menggunakan naskah otomatisasi Python launcher.py di root proyek untuk meluncurkan beberapa node dengan port P2P/RPC berbeda di komputer lokal secara instan guna mensimulasikan jaringan devnet validator konsensus dengan mudah!
