Transaction & WASM VM Fuzz Testing

Bagaimana Lumina L1 menerapkan instrumentasi kompiler Nightly (LLVM libFuzzer) guna menyaring pembagian nol, stack overflow, dan crash panic pada validator node akibat serangan transaksi korup atau bytecode WASM VM jahat.

Salah satu serangan Denial of Service (DoS) paling mematikan pada blockchain Layer 1 adalah pengiriman byte transaksi aneh atau bytecode smart contract jahat yang sengaja dirancang untuk memicu kegagalan sistem (*panic crash*) pada core node validator. Jika satu validator padam karena memproses byte tersebut, penyerang dapat menyebarkannya ke seluruh jaringan (P2P Gossipsub) untuk melumpuhkan seluruh blockchain secara instan.

Untuk mengamankan jaringan dari eksploitasi fatal ini, Lumina L1 meluncurkan **Transaction & WASM VM Fuzz Testing Suite** menggunakan instrumentasi tingkat lanjut `cargo-fuzz` (LLVM libFuzzer) yang memborbardir parser biner kita dengan miliaran data acak rusak.

💡 Analogi Nyata: Kotak Surat & Mesin Minuman Otomatis

1. Kotak Surat Kantor Pos (Fuzzing Transaksi): Bayangkan kantor pos menerima surat dari jutaan orang. Kebanyakan surat memiliki alamat yang jelas. Namun, ada pengirim iseng yang mengirim surat berisi tepung misterius, kertas robek-robek, atau ukuran surat raksasa tak beraturan (*corrupted bytes*). Sistem penyortir surat kita (parser bincode) harus mampu memeriksa surat aneh itu, berkata "ini bukan format surat sah" (*Return Err*), lalu membuangnya ke tempat sampah tanpa pernah membuat kantor pos meledak atau melukai petugas pos (*No Rust Panic*).

2. Vending Machine / Mesin Minuman (Fuzzing WASM VM): Ketika orang membeli minuman, mereka memasukkan koin. Penyerang mencoba memasukkan koin mainan dari es, kancing baju, atau koin besi berikat tali (*malicious WASM bytecode*). Mesin minuman (ContractExecutor WASM VM) harus secara instan menolak koin palsu tersebut secara aman, menghitung bahan bakar koin secara akurat (*gas metering*), dan mengeluarkan pesan error tanpa pernah membuat roda gigi internal mesin hancur, terbakar, atau macet selamanya (*No Executor Panic*).

1. Kenapa Kita Harus Melakukan Fuzzing?

Dalam bahasa pemrograman Rust, penanganan error desintesis menggunakan tipe data Result<T, E>. Namun, jika kode internal library mengalami keputusasaan (seperti membaca indeks array di luar batas tanpa proteksi atau pembagian nol), program akan memancarkan panic! yang langsung menghentikan proses aplikasi.

Fuzzing bertindak sebagai satpam biner otomatis. Ia menggunakan algoritma genetika untuk mengubah byte input secara acak (*mutative fuzzing*) guna mencari satu kombinasi byte yang dapat memicu panic!. Jika fuzzer berjalan berjam-jam tanpa menemukan panic, program tersebut terbukti kebal dari crash luar.

2. Target Fuzzing Lumina L1

Kita membagi target fuzzing menjadi dua area masuk yang paling rentan diserang secara remote:

Target 1: Deserializer Transaksi (fuzz_transaction_decoder)

Membombardir fungsi deserialisasi biner dari Gossipsub P2P jaringan. Memastikan bincode parser menolak input korup secara elegan:

fuzz_target!(|data: &[u8]| { // Membaca payload byte mentah dengan bincode standard config. // Parser HARUS mengembalikan Result::Err secara elegan tanpa memicu panic! let _ = bincode::decode_from_slice::(data, bincode::config::standard()); });

Target 2: WASM Contract VM Interpreter (fuzz_wasm_contract_vm)

Membombardir interpreter compiler WASM (wasmi) dengan kode mesin mentah. Memastikan konsumsi gas limit berfungsi deterministik:

fuzz_target!(|data: &[u8]| { if data.len() < 24 { return; } // Split byte input secara deterministik untuk parameter eksekusi let caller_addr: [u8; 20] = data[0..20].try_into().unwrap(); let method_len = (data[20] as usize) % 10; if data.len() < 21 + method_len { return; } let method_bytes = &data[21..21+method_len]; let method = std::str::from_utf8(method_bytes).unwrap_or("execute"); let remaining = &data[21+method_len..]; let mid = remaining.len() / 2; let bytecode = &remaining[..mid]; let params = remaining[mid..].to_vec(); // Mock read_state & write_state closures (tidak merusak database asli) let read_state = Box::new(|_key: &[u8]| -> Option> { None }); let write_state = Box::new(|_key: &[u8], _value: &[u8]| {}); let exec = EXECUTOR.get_or_init(|| ContractExecutor::new()); // Jalankan eksekusi WASM VM dengan gas limit 50,000 unit let _ = exec.execute(bytecode, method, params, caller_addr, read_state, write_state, 50000); });

3. Cara Menjalankan Fuzz Testing

Pengujian ini dijalankan pada toolchain Rust Nightly yang mengaktifkan compiler-sanitizers (ASan/MSan) untuk mendeteksi memory leak atau panic tersembunyi.

# 1. Install toolchain cargo-fuzz (jika belum ada) cargo install cargo-fuzz # 2. Jalankan fuzzing parser transaksi cargo fuzz run fuzz_transaction_decoder # 3. Jalankan fuzzing eksekusi WASM VM cargo fuzz run fuzz_wasm_contract_vm
