Simulasi Kehancuran Jaringan: 5 Skenario Chaos Menguji Batas Resiliensi Lumina L1

Dalam sistem terdesentralisasi, stabilitas tidak diperoleh dengan berharap kegagalan tidak akan terjadi, melainkan dengan merekayasa sistem agar selamat dari kegagalan terburuk sekalipun. Untuk memverifikasi keandalan konsensus HotStuff BFT, mesin kompilasi WASM, dan database staker di Lumina L1, tim pengembang meluncurkan skenario Chaos Testing Framework.

Dengan mengintegrasikan 7 validator genesis baru, jaringan diperluas menjadi 10-node cluster. Ini adalah ambang batas matematis minimum yang ideal untuk menjalankan stress test ekstrem, termasuk pemisahan wilayah jaringan (split-brain). Laporan ini merinci 5 skenario chaos ekstrem yang dirancang untuk merusak jaringan Lumina secara terkontrol dan bagaimana arsitektur otonom kami bertahan hidup.

ℹ️ Catatan Rekayasa: Versi terbaru dari launcher.py kini telah dilengkapi dengan sub-menu interaktif Option 16 (💥 TRIGGER CHAOS SCENARIO) yang memungkinkan pengembang memicu pemadaman, sabotase basis data, banjir transaksi, atau isolasi peer secara dinamis dari konsol terminal.

Skenario 1: Power Outage (Hard Kill Process)

Simulasi: Pemadaman listrik mendadak atau kerusakan perangkat keras total pada salah satu atau beberapa validator node utama yang sedang memproses blok.

Dalam launcher.py, skenario ini direpresentasikan dengan mengirimkan perintah taskkill /f /t /pid <PID> secara native pada Windows. Hal ini mematikan seluruh pohon proses (process tree) dari node target secara instan, tanpa memberikan kesempatan bagi node untuk melakukan graceful shutdown, menyimpan cache state, atau mengirim pesan offline kepada peer lainnya.

Respon Teoretis BFT

  • Toleransi kesalahan BFT (f) menjamin jaringan tetap aman selama 3f + 1 ≥ N. Dengan 10 node, konsensus tetap berjalan lancar meski 3 node mati serentak.
  • Sistem otomatis melewati slot node mati (leader timeout) dan menunjuk leader berikutnya.

Mitigasi & Pemulihan

  • Jika node mati melebihi batas 3 node, Dynamic Quorum Self-Healing otonom mendeteksi keabsenan validator secara berturut-turut.
  • Denominator quorum dipangkas secara adaptif setelah durasi timeout otonom tercapai.

Skenario 2: State Database Sabotage (DB Corruption)

Simulasi: Kerusakan media penyimpanan fisik (bad sector) atau manipulasi data biner secara ilegal pada berkas penyimpanan state lokal.

Skenario chaos ini mematikan node target, lalu membuka folder basis data otonom Sled (misal: data/node5/). Script rekayasa kemudian mencari berkas biner basis data di dalamnya dan menimpa 256 byte pertama dengan sampah byte acak (random entropy).

Saat validator dihidupkan kembali, basis data Sled akan mengalami kegagalan deserialisasi metadata atau memicu State Root Mismatch ketika memvalidasi blok berikutnya terhadap world state yang rusak.

⚠️ Proteksi Fatal: Desain node Lumina memastikan bahwa jika terdeteksi inkonsistensi internal atau kegagalan pembacaan database, node akan segera masuk ke kondisi Panic State & Safe Exit untuk mencegah pemancaran voting block invalid yang dapat berujung pada pemotongan saldo validator (slashing).

Skenario 3: Mempool Transaction Spam (Targeted RPC Attack)

Simulasi: Serangan Denial of Service (DoS) terkoordinasi yang membombardir mempool validator target dengan ribuan transaksi paralel bersponsor untuk menghabiskan sumber daya CPU dan RAM.

Skenario ini meluncurkan engine tx_bot asinkronus yang dikonfigurasi khusus untuk mengirimkan transaksi 0-koin bersponsor Sultan Alice langsung ke RPC port (misal: 9102) milik node terpilih. Bot memotong pembatasan sequential nonce konvensional dengan memproduksi keypair transien acak secara real-time pada setiap transaksi.

Mekanisme Pertahanan

  • Adaptive Gas Fee Market: Setiap lonjakan antrean mempool di node target memicu kenaikan harga gas minimum (priority fee) secara eksponensial.
  • Block-STM Concurrency: Mesin pemrosesan transaksi paralel spekulatif memproses transaksi non-konflik secara simultan untuk meloloskan kemacetan.

Hasil Pengujian

  • Meski node target mengalami kelebihan beban pemrosesan RPC, sistem routing mesh P2P Gossipsub membagi beban (load-balancing) dan memancarkan transaksi valid ke validator pendamping lainnya.

Skenario 4: P2P Regional Isolation (Split-Brain / Network Partition)

Simulasi: Terputusnya kabel serat optik bawah laut antarbenua atau kesalahan konfigurasi firewall regional yang memisahkan kluster validator menjadi dua kelompok terpisah.

Skenario chaos ini menghentikan validator target dan meluncurkannya kembali dengan parameter --bootnode dummy palsu (beralamat port yang tidak aktif). Hal ini mengisolasi node tersebut secara fisik dari topologi Gossipsub peer mesh utama Lumina. Node target hanya dapat berkomunikasi dengan dirinya sendiri atau subset regional kecilnya sendiri.

Hukum Quorum Dinamis & Zero-Fork Safety: Karena HotStuff BFT mewajibkan 2/3 + 1 suara setuju dari staker aktif untuk memproduksi blok bergaransi (committed), kluster regional terisolasi yang tidak memiliki porsi staking mayoritas tidak akan pernah bisa menyelesaikan konsensus. Mereka akan memproduksi blok kosong atau terhenti total (liveness fault), namun nol risiko terjadinya percabangan (fork) blockchain.

Skenario 5: Sybil Key Takeover Attack (Slashing & Jailing)

Simulasi: Penyerang sybil mencoba mendaftarkan beberapa validator staking dengan kunci BLS yang sama untuk merebut kendali consensus pool secara curang atau memancarkan suara ganda (double-voting).

Saat mesin pendeteksi kami (Sentinel Agent) mendeteksi adanya penandatanganan ganda di ketinggian blok yang sama oleh kunci BLS terdaftar, Sentinel segera menyiarkan bukti double-voting ke seluruh jaringan. Hal ini memicu fungsi Jailing & Slashing secara real-time:

Kesimpulan Uji Ketahanan

Hasil dari simulasi chaos menunjukkan bahwa Lumina L1 memiliki rancangan arsitektur yang kokoh. Batas toleransi kesalahan BFT (Fault Tolerance) bekerja secara presisi ketika diuji dengan Power Outage dan Regional Isolation. Penerapan Adaptive Gas Fee dan sistem auto-panic pada korupsi database membuktikan bahwa protokol mendahulukan keamanan state (safety) di atas segalanya, menjamin Lumina bebas dari kerentanan garpu data (zero-fork safety) sebelum diluncurkan di Testnet publik.
