Lumina Standards Library lsl-v0.1.0

Panduan arsitektur keamanan dan standar pembuatan token pintar (LTS-20/LTS-721) menggunakan pustaka standar resmi Lumina Standards Library (LSL).

Dalam ekosistem blockchain modern, keamanan dan standarisasi adalah pilar terpenting untuk mencegah eksploitasi kode. Lumina Protocol menyediakan Lumina Standards Library (LSL), sebuah pustaka kontrak pintar berkinerja tinggi, modular, dan hemat gas yang setara dengan OpenZeppelin di jaringan EVM. Pustaka ini dikompilasi mulus di lingkungan #![no_std] WebAssembly (WASM).

// Cara mengimpor pustaka standar di atas kontrak pintar Rust Lumina use lumina_std::standards::ownable::Ownable; use lumina_std::standards::pausable::Pausable; use lumina_std::standards::lts20::Lts20; use lumina_std::standards::lts721::Lts721; use lumina_std::standards::reentrancy_guard::ReentrancyGuard; use lumina_std::standards::access_control::AccessControl;

1. Pilar Keamanan & Standarisasi LSL

Pustaka standar ini dirancang untuk mengatasi risiko keamanan dan menyederhanakan kode boilerplate pengembang:

🔒 ReentrancyGuard (Anti-Exploit Vault)

Mencegah serangan pemanggilan ulang rekursif (Reentrancy) yang sering mengeksploitasi fungsi finansial pada dApps DeFi. Modul ini menyediakan status mutex lock stateful:

  • ReentrancyGuard::enter(): Memastikan kontrak tidak sedang dikunci sebelum melanjutkan, kemudian mengunci kontrak.
  • ReentrancyGuard::exit(): Membuka kembali kunci di akhir eksekusi fungsi.

🔑 AccessControl (Tata Kelola Multi-Role / RBAC)

Menggantikan sistem kepemilikan tunggal Ownable yang kaku dengan sistem peran berbasis identitas multi-level. Sempurna untuk dApps skala enterprise:

  • Mendefinisikan peran asimetris seperti ADMIN_ROLE, MINTER_ROLE, dan ORACLE_ROLE.
  • Mendukung fungsi pemberian (grant_role), pencabutan (revoke_role), dan pelepasan mandiri (renounce_role).

🛑 Pausable (Emergency Circuit Breaker)

Menyediakan fungsi sakelar darurat global untuk menghentikan transaksi mutasi aset ketika bug atau exploit terdeteksi di dApp.

📦 LTS-20 (Standard Token Fungible)

Standar representasi token fungible (seperti ERC-20) yang aman untuk pembuatan token utilitas, koin stabil (stablecoins), maupun tata kelola (governance tokens).

🖼️ LTS-721 (Standard NFT / Non-Fungible Token)

Logika aman untuk kepemilikan token unik (seperti ERC-721) yang dilengkapi metadata URI untuk representasi aset digital unik/NFT.

2. Contoh Smart Contract Komplit (example-sc.rs)

Di bawah ini adalah implementasi nyata dari kontrak token USDT LTS-20 resmi yang menggunakan LSL untuk meminimalkan boilerplate hingga 50% serta menyematkan logika Blacklist kustom di luar standar library:

// ============================================================================ // LTS-20 Token Standard — Lumina Protocol // Adapted to use the official Lumina Standards Library (LSL) // Features: Transfer, Approve, Mint, Burn, Pause, Ownership, Custom Blacklist // ============================================================================ #![no_std] use lumina_std::*; use lumina_std::standards::ownable::Ownable; use lumina_std::standards::pausable::Pausable; use lumina_std::standards::lts20::Lts20; #[lumina_contract] pub mod lts20_token { use super::*; // ────────────── CONSTANTS ────────────── const NAME: &str = "Tether USDT"; const SYMBOL: &str = "USDT"; const DECIMALS: u8 = 18; const MAX_SUPPLY: u128 = 1_000_000_000 * 10u128.pow(18); // ────────────── CUSTOM STORAGE KEYS ────────────── fn key_blacklist(addr: &Address) -> String { format!("blacklist:{}", addr) } fn key_minter(addr: &Address) -> String { format!("minter:{}", addr) } // ────────────── CUSTOM SECURITY GUARDS ────────────── fn not_blacklisted(addr: &Address) { let banned: bool = storage::read(key_blacklist(addr)).unwrap_or(false); assert!(!banned, "Address is blacklisted"); } fn valid_address(addr: &Address) { assert!(!addr.is_zero(), "Invalid zero address"); } // ────────────── INITIALIZE ────────────── #[init] pub fn initialize() { let initial_supply: u128 = 1_000_000 * 10u128.pow(18); let owner = get_caller(); valid_address(&owner); // Inisialisasi pustaka standar Ownable::initialize(&owner); Pausable::initialize(false); // Minting suplai awal menggunakan LTS-20 standard Lts20::mint(&owner, initial_supply); } // ────────────── CORE VIEWS ────────────── #[view] pub fn name() -> String { NAME.to_string() } #[view] pub fn symbol() -> String { SYMBOL.to_string() } #[view] pub fn total_supply() -> u128 { Lts20::total_supply() } #[view] pub fn balance_of(account: Address) -> u128 { Lts20::balance_of(&account) } #[view] pub fn owner() -> Address { Ownable::owner().expect("Owner not initialized") } // ────────────── TRANSACTION ENDPOINTS ────────────── #[endpoint] pub fn transfer(to: Address, amount: u128) { Pausable::assert_not_paused(); let from = get_caller(); not_blacklisted(&from); not_blacklisted(&to); Lts20::transfer(&from, &to, amount); } #[endpoint] pub fn mint(to: Address, amount: u128) { Pausable::assert_not_paused(); let caller = get_caller(); let owner_addr = Ownable::owner().unwrap(); let caller_is_minter = storage::read(&key_minter(&caller)).unwrap_or(false); assert!(caller == owner_addr || caller_is_minter, "Not authorized"); Lts20::mint(&to, amount); } }

3. Manfaat Arsitektur Modular LSL

💡 Keandalan Kode: Dengan mendelegasikan fungsionalitas inti (seperti pengelolaan kunci, pencatatan event, kalkulasi balance) ke perpustakaan resmi yang telah diaudit, pengembang eksternal terhindar dari bug overflow, kebocoran data state, atau penyalahgunaan izin administrasi.

4. Metrik API Standar

Modul & Metode Penjelasan Fungsi Keamanan
Ownable::assert_only_owner() Memvalidasi bahwa penandatangan transaksi adalah pemilik sah kontrak. Abort jika gagal.
Pausable::assert_not_paused() Menolak kelanjutan fungsi jika status kontrak pintar sedang di-pause oleh admin.
ReentrancyGuard::enter() Mengaktifkan kunci rekursi di awal transaksi finansial sensitif.
AccessControl::grant_role(role, account) Memberikan hak akses khusus bagi peran tertentu (dikendalikan oleh admin peran terkait).
