Aliran Event Real-Time: JSON-RPC 2.0 WebSockets Pub/Sub Bidirectional

Bagaimana Lumina L1 memancarkan notifikasi blok baru, transaksi mempool, filter logs, dan aktivitas akun secara real-time menggunakan engine Pub/Sub asinkronus dua arah di atas Axum WebSocket.

STATUS SISTEM: WEBSOCKET SERVICE LIVE DI PORT 9098 (/ws)

Dalam ekosistem dApp (Decentralized Application) modern, kemampuan untuk menerima pembaruan status blockchain secara instan tanpa melakukan polling (permintaan HTTP berulang) adalah kunci kenyamanan pengguna. Mulai dari pembaruan saldo dompet, notifikasi keberhasilan transaksi, hingga pemantauan cetakan blok baru, semua membutuhkan koneksi persisten berlatensi rendah.

Lumina L1 secara resmi mengintegrasikan JSON-RPC 2.0 WebSockets Pub/Sub Bidirectional langsung ke dalam crate api dengan arsitektur asinkronus terdistribusi berbasis Axum. Implementasi ini memungkinkan client untuk mengirim perintah kontrol dan berlangganan ke saluran data real-time secara dua arah melalui satu koneksi TCP tunggal.

💡 ANALOGI NYATA: Ketuk Pintu Berulang vs Lonceng Otomatis Pintu Masuk

1. HTTP Polling (REST/JSON-RPC Biasa): Seperti Anda menunggu paket kurir di rumah, lalu setiap 5 detik Anda membuka pintu dan bertanya ke jalan: *"Apakah paket saya sudah sampai?"*. Ini sangat melelahkan bagi Anda (CPU overhead) dan mengganggu lingkungan sekitar (pemborosan bandwidth jaringan).

2. WebSocket Pub/Sub (Lonceng Otomatis): Seperti memasang bel pintu pintar. Anda cukup mendaftarkan bel tersebut sekali (lumina_subscribe). Kurir datang, bel berbunyi otomatis secara instan. Anda dapat bersantai tanpa memikirkan antrean status, dan dApp Anda akan terupdate dalam milidetik setelah block baru dicetak.

Metode Kontrol & Topik Langganan

Protokol WebSocket Lumina mematuhi spesifikasi JSON-RPC 2.0 secara ketat. Handshake awal akan disambut oleh notifikasi sambutan lumina_connected, setelah itu client dapat menggunakan metode berikut:

1. Topic: newHeads

Mengalirkan objek header blok terbaru segera setelah disepakati oleh konsensus BFT Hotstuff. Berguna untuk sinkronisasi antarmuka UI blockchain explorer.

2. Topic: pendingTransactions

Mengalirkan hash transaksi baru sesaat setelah masuk ke mempool lokal sebelum dipaketkan ke dalam blok baru.

3. Topic: addressTransactions

Memfilter dan mengirimkan data transaksi yang memengaruhi alamat target tertentu (baik sebagai pengirim maupun penerima), lengkap dengan validasi Bech32m.

4. Topic: logs

Menyaring log keluaran eksekusi smart contract WASM berdasarkan alamat kontrak pintar dan topik event tertentu.

Validasi Bech32m Alamat Ketat

Sesuai dengan spesifikasi keamanan blockchain Lumina L1, setiap parameter alamat yang didaftarkan ke subskripsi addressTransactions wajib melalui tahap validasi format Bech32m (awalan lumina1...). Jika format tidak sesuai, server akan langsung menolak permintaan dengan kode error standar JSON-RPC 2.0 -32602 (Invalid Params) dan pesan "Invalid address format".

Contoh Request Langganan (Subscription):

{ "jsonrpc": "2.0", "method": "lumina_subscribe", "params": ["addressTransactions", { "address": "lumina18l3cd3f8kfa5576hqvulqrp6n0m3w00432cvd8" }], "id": 1 }

Contoh Response Sukses:

{ "jsonrpc": "2.0", "result": "0xedd16e92043a96e2", "id": 1 }

Contoh Response Error (Alamat Invalid):

{ "jsonrpc": "2.0", "error": { "code": -32602, "message": "Invalid address format" }, "id": 1 }

Pembatalan Langganan (Unsubscribe)

Untuk menghindari kebocoran memori pada server, client disarankan melakukan unsubscribe jika sudah tidak memerlukan pembaruan event dengan metode lumina_unsubscribe menggunakan ID subskripsi heksadesimal yang sebelumnya diperoleh:

{ "jsonrpc": "2.0", "method": "lumina_unsubscribe", "params": ["0xedd16e92043a96e2"], "id": 99 }

Performa Skalabilitas Asinkronus

Di balik layar, server Axum WebSocket Lumina memutar event loop asinkronus menggunakan perintah non-blocking tokio::select! secara terisolasi per koneksi client. Ini berarti data dialirkan dari broadcast channel explorer_tx secara langsung tanpa membutuhkan global mutex locks yang menghambat kinerja CPU, menjamin TPS tinggi (Transactions Per Second) tetap terjaga meskipun melayani ribuan koneksi secara simultan.
