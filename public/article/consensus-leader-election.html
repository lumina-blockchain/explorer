Consensus: Leader Election & Hybrid Validator Registry

Bagaimana Lumina menjamin kelangsungan konsensus HotStuff BFT melalui penggabungan validator dinamis dan pemilihan leader deterministik tanpa overhead jaringan.

Dalam jaringan blockchain terdesentralisasi Layer 1 (L1), kelangsungan produksi blok sangat bergantung pada penentuan **Leader** (validator yang bertugas memproses transaksi dan mengusulkan blok). Jika pemilihan leader memakan waktu lama atau melibatkan negosiasi antar node yang rumit, throughput transaksi jaringan akan anjlok drastis.

Lumina memecahkan masalah ini secara revolusioner melalui skema **Deterministic Round-Robin** dengan **Hybrid Validator Registry**. Sistem ini mampu menggabungkan validator statis bawaan sejak awal jaringan (Genesis) dengan staker baru yang mendaftar secara dinamis saat jaringan sedang berjalan, menjamin keadilan mutlak tanpa ada pesan komunikasi tambahan (*Zero Communication Overhead*).

⚡ Pembaruan Sistem: Mulai rilis v1.3, mekanisme penentuan leader telah ditingkatkan penuh untuk mengintegrasikan active staker dari StateManager secara dinamis dan real-time tanpa perlu me-restart node!

Alih-alih hanya mengandalkan daftar validator statis yang kaku, Lumina menggabungkan dua sumber registrasi secara real-time di setiap putaran tinggi blok:

(Konsisten di Seluruh Node)

Gabungan daftar ini kemudian diurutkan secara **alfabetis** berdasarkan alamat Bech32 masing-masing validator. Hal ini wajib dilakukan agar seluruh node di seluruh dunia menghasilkan urutan baris antrean staker yang **100% identik dan konsisten**!

2. Implementasi Rust: Penentuan Leader Deterministik

Di bawah ini adalah kode sumber riil dari engine konsensus Lumina di dalam crates/consensus/src/lib.rs yang menangani pencarian leader untuk tinggi blok tertentu:

/// Tentukan siapa Leader untuk tinggi blok tertentu secara deterministik. pub fn get_leader(&self, height: u64) -> Address { // 1. Ambil Validator Genesis dari StakingState let mut all_validators: Vec<Address> = self.staking.get_validators() .iter().map(|v| v.address.clone()).collect(); // 2. Gabungkan dengan Validator Baru yang terdaftar dinamis di StateManager for entry in self.state.active_validators.iter() { let addr = entry.value().clone(); if !all_validators.contains(&addr) { all_validators.push(addr); } } if all_validators.is_empty() { return Address([0u8; 20]); } // 3. Urutkan alfabetis agar kocokannya 100% konsisten di semua node all_validators.sort_by(|a, b| a.to_string().cmp(&b.to_string())); // 4. Pilih Leader menggunakan rumus matematika Round-Robin sisa bagi let index = (height % (all_validators.len() as u64)) as usize; all_validators[index].clone() }

3. Siklus Hidup Proposisi Blok HotStuff

Setelah leader terhitung oleh rumus di atas, proses proposisi blok dikelola dengan jeda waktu yang presisi:

T + 0 detik (Round Start)

Tinggi blok baru dimulai. Leader yang sah langsung teridentifikasi oleh rumus matematika di atas. Seluruh validator mulai mengumpulkan transaksi dari mempool.

T + 5 detik (Block Proposal Phase)

Leader mulai membungkus transaksi mempool ke dalam blok baru, membubuhkan State Root, dan menyiarkannya (broadcast) ke seluruh validator di jaringan P2P.

T + 15 detik (Timeout & Skip Leader Phase)

Jika dalam 15 detik jaringan belum menerima proposal blok yang sah dari leader tersebut (misal karena server leader mati atau internet putus), sistem masuk ke mode darurat **Skip Leader**.

4. Penanganan Kegagalan: Skip Leader Takeover

Blockchain Lumina tidak boleh berhenti beroperasi hanya karena satu server validator staker mengalami mati lampu atau masalah teknis:

Backup Leader Activating

Setelah timeout 15 detik terpicu di semua node secara paralel, node secara otomatis menunjuk validator urutan berikutnya: (LeaderIndex + 1) sebagai Backup Leader.

Zero Desynchronization

Backup Leader langsung mengambil alih kepemimpinan, menyusun proposal blok alternatif, dan menyebarkannya. Konsensus berjalan lancar tanpa desinkronisasi State Root!

Pertanyaan Umum (FAQ)

Apakah staker baru langsung berhak jadi leader setelah mengirim koin?

Ya, langsung di blok berikutnya! Begitu transaksi STAKE terkonfirmasi masuk ke dalam blok, akun staker tersebut langsung terdaftar di active_validators StateManager dan ikut serta dalam kocokan leader di tinggi blok selanjutnya secara real-time.

Apakah skema Alphabetical Sorting ini adil?

Sangat adil. Karena sisa bagi tinggi blok (`height % total_validators`) terus bertambah 1 di setiap blok, giliran menjadi leader akan terus berputar secara merata ke seluruh validator yang ada di dalam antrean terlepas dari urutan huruf nama alamat mereka.
